# Ранние издания Рипы: что можно сделать отдельной книгой библиотеки

Разведка. В репозиторий ничего не скачивалось (метаданные и OCR-тексты читались временно в `/tmp`), код и данные не менялись. Дата: 2026-11-16.

## Главное

- **Наши гравюры** (Baudoin, Paris 1677, Jacques de Bie) — круглые медальоны-фигурки де Би (ок. 450 гравюр); парижские издания 1636/1637/1643/1644 — **то же семейство** (де Би перерисовал оригинальные ксилографии Рипы в линейные фигуры в круглых рамках; 1677 — перепечатка 1644 г. с теми же досками). Это не «другие» иллюстрации, брать их смысла нет.
- **Другие иллюстрации** — только в итальянских изданиях: малые ксилографии, по одной на часть статей (иллюстрирована не каждая статья). Первое иллюстрированное — **Roma 1603** (Lepido Facij). Издание 1593 — без иллюстраций.
- **Рекомендация: Roma 1603** (Heidelberg, IIIF, Public Domain Mark; резерв — три экземпляра на Internet Archive). Малый объём (≈200 тыс. слов, 554 страницы, ~150 ксилографий), оригинальный набор гравюр, цитируется как «то самое» иллюстрированное издание. Запасной вариант — Padova 1611 (то же по объёму, больше гравюр).
- **Сайт.** 1603 целиком по нашим стандартам — ≈ 190 МБ; сайт сейчас ≈ 970 МБ, лимит GitHub Pages — 1 ГБ ⇒ **нужен отдельный репозиторий/сайт** (или сканы страниц брать с IIIF Heidelberg).

## 2. Оценка объёма для трёх лучших

Опорные цифры наших данных: статья Рипы (1677) — ≈118 тыс. слов, 444 статьи; на гравюру у нас уходит ≈ 150 КБ (основная) + ≈ 245 КБ (`_display`) + 13 КБ (миниатюра) ≈ **0,4 МБ**; скан страницы ≈ 270 КБ. Весь `books/iconologie` — 341 МБ (гравюры 191, сканы 140, миниатюры 6,5). Ксилографии 1603 мелкие (≈5×6 см) — для них 0,25–0,3 МБ на гравюру.

| | Roma 1603 | Padova 1611 | Padova 1618 |
|---|---|---|---|
| страниц текста | 554 | ≈600 | ≈710 |
| объём текста | ≈200 тыс. слов (≈1,7 нашего) | ≈185 тыс. слов | ≈350 тыс. слов (≈3×) |
| статей | 684 (лит.) | ≈700–800 | ≈1000+ |
| гравюр | ≈150 (из ≈180 блоков) | ≈200 | ≈300–330 |
| гравюры на сайте (≈0,3 МБ) | ≈45 МБ | ≈60 МБ | ≈95 МБ |
| сканы страниц (≈250 КБ) | ≈140 МБ | ≈150 МБ | ≈180 МБ |
| итого (гравюры + сканы) | **≈190 МБ** | ≈210 МБ | ≈275 МБ |

**Лимит 1 ГБ.** Сайт сейчас ≈ 970 МБ (папка `books/cartari` 662 МБ, `books/iconologie` 341 МБ, `books/verrien` 152 МБ и т. д.); добавление даже ≈115 МБ (сканы вдвое легче, 900×1300, q70) уже превышает 1 ГБ. Варианты:
1. **Отдельный репозиторий + свой GitHub Pages** (например, `library-ripa1603`), с тем же `app.js`/`app.css` (код общий — подключать как подмодуль или копировать при сборке), ссылка из главной страницы библиотеки. Свой лимит 1 ГБ. Предпочтительно.
2. Сайт на Cloudflare Pages (уже используется для 94hours.com): ограничения — число файлов (20 000) и 25 МБ на файл, общий размер не лимитирован жёстко.
3. Для 1603 сканы страниц не хранить, а брать с **IIIF Heidelberg** (`…/iiif/2/ripa1603%3A<лист>.jpg/full/…`): ссылка + атрибуция, экономит ≈140 МБ; риск — зависимость от стороннего сервера (антибот Heidelberg на веб-страницах, но IIIF-картинки и манифест отдавались без обхода) и CORS.
4. Уменьшать существующие книги (например, сканы Картари) — отдельная большая задача.

Размер `.git` уже 5,3 ГБ при рабочем каталоге ≈ 6,7 ГБ (включая служебное); новые большие бинарники в этот репозиторий лучше не класть.

## 3. Рекомендация

**Брать Roma 1603** (Facij). Причины: первое иллюстрированное издание — исторически «то самое» и по оформлению (малые ксилографии, части статей без картинок) заметно отличается от нашего де Би; объём разумный (≈1,7× нашего по тексту, ≈150 гравюр, а не 400); есть открытый IIIF Heidelberg с явной лицензией PDM и 3–4 независимых копии на Internet Archive в более высоком разрешении (можно сверять два экземпляра при сомнениях); язык оригинала один (итальянский, изредка латынь). Вариант «в одну книгу с нашей Рипой» не годится: разные язык, состав статей, иллюстрации, нумерация. Запасной — Padova 1611 (тот же размер, +30% гравюр, но экземпляры только на IA); более полные 1618/1630 имеют в 2–3 раза больше текста и гравюр.

**Порядок работ (по схеме нашей Рипы):**
1. Каркас: схема данных, `book.json` (`sourceIsFrench: false` — оригинал итальянский), структура `entries.json` (часть статей без гравюры — `textOnly`), сканы страниц, миниатюры; решение о хостинге (отдельный репозиторий).
2. Гравюры: вырезка ≈150 ксилографий (редактор обрезки `tools/crop-editor`, затем сборка `_display`, миниатюр); сверка с текстом статьи.
3. Транскрипция итальянского текста: 3–5 независимых проходов по сканам разными проверяющими + арбитраж спорных мест (≈554 страницы × 3–5 = 1700–2800 страничных чтений + арбитраж); орфография печати (ſ→s, лигатуры, сокращения как в печати); сверка IIIF Heidelberg ↔ IA при расхождениях чтения.
4. Перевод RU/EN/FR (итальянский → три языка; на FR и EN — по итальянскому, а не через русский), термины и имена по глоссарию (взять из Картари и нашей Рипы: итальянская лексика пересекается с Картари): ≈200 тыс. слов × 3 языка.
5. Аудит: перевод против оригинала (два независимых прохода), аудит транскрипции по сканам (второй независимый проход), правки, повторная проверка.
6. Проверки сайта (`check_*`, языки, прокрутка), сборка, публикация.

**Грубая оценка трудоёмкости** (в токенах агентов, порядок величины; по аналогии с тем, что ушло на нашу Рипу, Картари и Гроссона): транскрипция 4 прохода + арбитраж ≈ 3–5 млн; перевод 3 языка ≈ 1–2 млн (выход ≈ 1 млн); аудит ≈ 2–3 млн; гравюры, сайт, тесты — ≈ 0,5–1 млн; **итого ≈ 7–11 млн токенов**, то есть порядка 15–25 длинных сессий. Ручные решения владельца: рамки гравюр (≈150, редактор), спорные чтения, структура (какие статьи без гравюры), хостинг.

## Оговорки

- Числа гравюр и слов — по автоматической разметке/OCR и литературе, ±15–20%; число статей кроме 1603 не проверялось.
- Лицензии на IA у части экземпляров (Duke, UIUC, JCB) не указаны в метаданных; по возрасту книги — общественное достояние, условия репродукции библиотек (Duke, Getty, Heidelberg) стоит проверить перед публикацией; у Heidelberg явный PDM 1.0.
- Страницы Heidelberg за антиботом: манифест IIIF и картинки отдавались без обхода, веб-страницы — нет (WebFetch получил «Access Denied»).
